Branded Short Links splits its work across two runtimes — a <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Worker</Terminology> that routes requests and fires analytics <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> at the edge, and a Node.js CLI that manages configuration locally.

## System Overview

The project has two entry points running on different runtimes:

```mermaid
graph TD
    subgraph Edge["Cloudflare Worker (Edge)"]
        direction TB
        A1[Parse environment] --> A2[Check HTTP method]
        A2 --> A3[Match shortcode]
        A3 --> A4[Fire trackers]
        A3 --> A5[Return redirect / fallback / landing page]
    end

    subgraph Local["Node.js (Local)"]
        direction TB
        B1[Interactive menu] --> B2[Read/write config]
        B2 --> B3[Validate config]
        B3 --> B4[Generate wrangler.toml]
        B4 --> B5[Deploy via Wrangler]
    end

    subgraph Shared["Shared Library"]
        C1[Zod schemas]
        C2[Regex patterns]
    end

    HTTP[HTTP Request] --> Edge
    CLI[CLI Command] --> Local
    Shared -.-> Edge
    Shared -.-> Local
```

The <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> handles incoming HTTP requests at the edge. The CLI manages the configuration file that the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> reads at runtime.

## Request Flow

When a request arrives at the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Worker</Terminology>:

1. **Parse environment** — The <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> reads `SETTINGS`, `LINKS`, and `TRACKERS` from <Terminology title="Cloudflare's Workers deployment CLI" to="/docs/reference/terminology#wrangler">Wrangler</Terminology> environment variables (injected as JSON strings during deployment). It validates them against the Zod <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> schema.

2. **Check HTTP method** — Only `GET` and `HEAD` requests are processed. All other methods return `405 Method Not Allowed`.

3. **Match <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology>** — The URL pathname is stripped of its trailing slash and matched against the configured <Terminology title="single shortcode-to-URL config entry" to="/docs/reference/terminology#link-item">link items</Terminology>.

4. **Route the response:**

| Condition                                                                                                                                                               | Response                                                                                                                                                                                     |
|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">Shortcode</Terminology> matched                                         | Fire <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> in background, redirect with configured HTTP status     |
| No match, <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology> configured, root path (`/`) | Redirect to <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback URL</Terminology> origin only (always 301)                   |
| No match, <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology> configured, other path      | Redirect to <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology> origin + original path/query/hash (always 301) |
| No match, no <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology>, root path (`/`)         | Serve the branded <Terminology title="branded page served at the root" to="/docs/reference/terminology#landing-page">landing page</Terminology> (200)                                        |
| No match, no <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology>, other path              | Serve the <Terminology title="page shown when nothing else matches" to="/docs/reference/terminology#404-page">404</Terminology> not-found page (404)                                         |

5. **Log event** — Every request logs a structured JSON payload to `console.info()` with the matched <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology> (or `null`), redirect URL, HTTP response code, and <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">tracker</Terminology> names. You can view these logs in real time with `npm run tail`. Example payload:

```json
{
  "shortcode": "/github",
  "redirect_url": "https://github.com/yourname",
  "http_response": 301,
  "trackers": ["my-ga4", "my-ntfy"]
}
```

## Tracker Dispatch

<Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">Trackers</Terminology> fire in the background so the redirect response is returned immediately:

```mermaid
graph TD
    Match[Shortcode Matched] --> WaitUntil(["ctx.waitUntil()"]):::muted --> AllSettled(["Promise.allSettled()"]):::muted
    Match --> Redirect["Response.redirect()"] --> Client[Client]

    AllSettled --> GA4[GA4]
    AllSettled --> Facebook[Facebook]
    AllSettled --> PostHog[PostHog]
    AllSettled --> ntfy[ntfy]
    AllSettled --> NRP[Reverse Proxy for ntfy]
    AllSettled --> PlainText[Plain Text]
```

- All <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> fire in parallel via `Promise.allSettled()`.
- Individual failures don't affect other <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> or the redirect.
- Each <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">tracker</Terminology> type makes its own HTTP request to the respective service's API endpoint.

## Landing Page

When a GET request hits the root path (`/`) and no <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback URL</Terminology> is configured, the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> serves a branded HTML page:

- Project name and description.
- Link to the GitHub repository.
- Dark mode support via CSS custom properties (`prefers-color-scheme`).
- Fade-in animation.

When `show_response_output` is `true`, an expandable `<details>` element shows the <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> with sensitive values masked (`••••••`). The masking function replaces:

- **Links** — `redirect_url` on every <Terminology title="single shortcode-to-URL config entry" to="/docs/reference/terminology#link-item">link item</Terminology>.
- **<Terminology title="Google Analytics 4 tracker type" to="/docs/reference/terminology#ga4">GA4</Terminology> <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>** — `measurement_id` and `api_secret`.
- **<Terminology title="Meta Pixel PageView tracker type" to="/docs/reference/terminology#facebook">Facebook</Terminology> <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>** — `pixel_id`.
- **<Terminology title="push notification tracker type" to="/docs/reference/terminology#ntfy">ntfy</Terminology> <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>** — `server` and `token`.
- **<Terminology title="single-URL ntfy notification tracker type" to="/docs/reference/terminology#reverse-proxy-for-ntfy">Reverse Proxy for ntfy</Terminology> <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>** — `url` and optionally `token`.
- **<Terminology title="PostHog event capture tracker type" to="/docs/reference/terminology#posthog">PostHog</Terminology> <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>** — `host` and `api_key`.
- **<Terminology title="plain-text webhook tracker type" to="/docs/reference/terminology#plain-text">Plain-text</Terminology> <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>** — `url` and optionally `token`.

Settings (including `worker_name`, `base_domain`) and the `fallback_url` are shown unmasked.

A similar <Terminology title="page shown when nothing else matches" to="/docs/reference/terminology#404-page">404 page</Terminology> is served for unmatched paths when no <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback URL</Terminology> is configured.

## Configuration Pipeline

```mermaid
graph TD
    Config[config.json] --> Step1["1. Resolve API token"]
    Step1 --> Step2["2. Validate config (Zod)"]
    Step2 --> Step3["3. Verify permissions"]
    Step3 --> Step4["4. Generate wrangler.toml"]
    Step4 --> Step5["5. Deploy worker"]
    Step5 --> Step6["6. Print summary"]
```

The <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> file is never deployed directly. The CLI serializes each section as a JSON string into <Terminology title="Cloudflare's Workers deployment CLI" to="/docs/reference/terminology#wrangler">Wrangler</Terminology> environment variables.

The <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> parses these strings back into objects at runtime.

## Error Strategy

|---------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

Returns JSON error response on failure.                                                                                                                                                                                                                                                                                                                                                        |
| <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">Config</Terminology> parsing                | Zod `safeParse` at request time validates env vars. | <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">Shortcode</Terminology> matching                  | No match falls through to <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback URL</Terminology>, <Terminology title="branded page served at the root" to="/docs/reference/terminology#landing-page">landing page</Terminology>, or <Terminology title="page shown when nothing else matches" to="/docs/reference/terminology#404-page">404</Terminology>. Never crashes. |
| <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">Tracker</Terminology> dispatch           | `Promise.allSettled()` catches individual failures silently. Never blocks.                                                                                                                                                                                                                                                                                                                                                               |
| CLI commands                                                                                                                                      | Try/catch at command level. Chalk-formatted errors. Non-zero exit code.                                                                                                                                                                                                                                                                                                                                                                  |
| <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">Config</Terminology> validation             | Zod schemas catch type mismatches, missing fields, invalid URLs, duplicates.                                                                                                                                                                                                                                                                                                                                                             |

## Data Collected Per Request

When <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> fire, they can access these data points from the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Workers</Terminology> runtime. Each <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">tracker</Terminology> type selects the subset of data relevant to its API. See [Trackers](/docs/configuration/trackers/) for what each type sends.

|----------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `shortcode`    | The matched <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology> path (e.g., `/github`).   |

### Why Direct Tracking?

Traditional tag management systems like Google Tag Manager rely on embedding JavaScript in the browser. This doesn't work for URL shorteners because browsers immediately follow the `Location` header on a 3xx redirect response instead of loading the response body, so embedded analytics scripts never execute.

Branded Short Links solves this by firing analytics <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> server-side from the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Worker</Terminology>, bypassing the browser entirely. This means:

- No client-side JavaScript required.
- No dependency on browser-side tag containers.
- Tracking works even when JavaScript is blocked or disabled.
- No `http-equiv` meta refresh redirects (which are bad for SEO).
