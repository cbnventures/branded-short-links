Manage links, <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>, private app access, settings, and deployments through the `branded-short-links` command-line interface.

## Usage

The CLI is available as `branded-short-links` or the shorter alias `bsl`:

```bash
# Interactive mode (no arguments)
bsl

# Direct command
bsl <command>
```

When you run `bsl` with no arguments, the interactive menu launches. When you pass a command, it runs directly and exits.

## Interactive Menu

The interactive menu provides a guided experience for managing your entire configuration. It presents a main menu with these options:

- **Manage Links** — Sub-menu with: Add, Edit, Remove, Set <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">Fallback URL</Terminology>, Back.
- **Manage <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">Trackers</Terminology>** — Sub-menu with: Add, Edit, Remove, Back.
- **Settings** — Update <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> name, <Terminology title="domain your shortcodes live on" to="/docs/reference/terminology#base-domain">base domain</Terminology>, and debug output toggle.
- **Deploy** — Run the full deployment pipeline to <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Workers</Terminology> (with interactive <Terminology title="Cloudflare credential authorizing CLI deployments" to="/docs/reference/terminology#api-token">token</Terminology> prompting if needed). See [Deployment](/docs/deployment/cloudflare/).
- **Exit** — Quit the menu. You can also press Ctrl+C at any prompt.

Changes are saved to `config.json` immediately after each operation (add, edit, remove, etc.). There's no separate save step.

See [Configuration](/docs/configuration/settings/) for the full <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> reference.

### Config File Selection

When launching the interactive menu, the CLI checks for `config.json` in the current directory, project root, and user config directory:

- **Multiple found** — You're prompted to choose which <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> file to use.
- **One found** — That <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> file is used automatically.
- **None found** — A new <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> file is created in the user config directory (`~/.config/branded-short-links/config.json`).

## Commands

### `bsl access add <username>`

Add a private app user and generate an <Terminology title="deployer-managed credential for the private app API" to="/docs/reference/terminology#access-key">access key</Terminology>. The username is trimmed and converted to lowercase.

```bash
# Five words; easiest to enter manually
bsl access add jacky

# Five compact four-character chunks
bsl access add jacky --format compact

# Long copy-and-paste key
bsl access add jacky --format random
```

The default format is `memorable`. The CLI writes the username and generated key to `config.json` and prints the credential for immediate use.

### `bsl access rotate <username>`

Replace an existing user's key. Choose `memorable`, `compact`, or `random`; the default is `memorable`.

```bash
bsl access rotate jacky --format random
```

The old key stops working after the updated config is redeployed.

### `bsl access remove <username>`

Remove a private app user. Removing the last user also removes the optional `app_access` section, so the private endpoint is omitted from the generated Worker variables.

```bash
bsl access remove jacky
```

### `bsl validate`

Validate the configuration file against the schema and check for duplicates.

```bash
bsl validate
```

Checks performed:

- Schema validation (field types, required fields, URL formats).
- Duplicate <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology> detection.
- Duplicate <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">tracker</Terminology> name detection.
- Duplicate private app username detection and reserved endpoint protection.

Prints "Config is valid." on success, or lists all validation errors.

### `bsl generate`

Generate a `wrangler.toml` file from the current configuration.

```bash
bsl generate
```

Outputs a <Terminology title="Cloudflare's Workers deployment CLI" to="/docs/reference/terminology#wrangler">Wrangler</Terminology> configuration file with:

- <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Worker</Terminology> name and compatibility date (set to current date).
- Main entry pointing to the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Worker</Terminology> included with the installed package.
- <Terminology title="Workers route bound to the full path" to="/docs/reference/terminology#custom-domain">Custom domain</Terminology> routes for the <Terminology title="domain your shortcodes live on" to="/docs/reference/terminology#base-domain">base domain</Terminology> (and `www.` variant for two-part domains).
- Stringified `SETTINGS`, `LINKS`, and `TRACKERS` as <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Worker</Terminology> environment variables, plus `APP_ACCESS` when configured.

When run standalone, the generated file doesn't include the `account_id` field. The `bsl deploy` command generates a `wrangler.toml` with `account_id` included (derived from the permission verification step).

For local development, the standalone output is sufficient.

### `bsl deploy`

Run the full deployment pipeline to <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Workers</Terminology>.

```bash
bsl deploy
```

The deploy process runs these steps in order:

1. **Resolve <Terminology title="Cloudflare credential authorizing CLI deployments" to="/docs/reference/terminology#api-token">API token</Terminology>** — Loads from `.env` or `CLOUDFLARE_API_TOKEN` env var. When run from the interactive menu, prompts you to enter one if not found.
2. **Validate <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology>** — Runs schema and duplicate checks.
3. **Verify permissions** — Checks the <Terminology title="Cloudflare credential authorizing CLI deployments" to="/docs/reference/terminology#api-token">API token</Terminology> has Workers Scripts, Workers Routes, and Email Routing Rules permissions.
4. **Generate `wrangler.toml`** — Writes the deployment configuration with account ID, routes, and serialized <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> vars.
5. **Deploy <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology>** — Runs `wrangler deploy` with the generated <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology>.
6. **Print summary** — Displays all configured <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcodes</Terminology> with URLs, redirect codes, and active <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>.

See [Deployment](/docs/deployment/cloudflare/) for the full walkthrough.

### `bsl links remove <shortcode>`

Remove a <Terminology title="single shortcode-to-URL config entry" to="/docs/reference/terminology#link-item">link</Terminology> by its <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology> path.

```bash
bsl links remove /github
```

The <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology> must include the leading `/`.

### `bsl trackers remove <name>`

Remove a <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">tracker</Terminology> by its name.

```bash
bsl trackers remove my-ga4
```

## npm Scripts

If you're working within the project repository, these npm scripts are available from the workspace root:

| Script           | What It Does                                                                                                                                                                       |
|------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `npm run manage` | Launch the interactive <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> management menu.                 |
| `npm run dev`    | Start a local development server via <Terminology title="Cloudflare's Workers deployment CLI" to="/docs/reference/terminology#wrangler">Wrangler</Terminology>.                    |
| `npm run build`  | Build the CLI and <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology> for deployment.            |
| `npm run check`  | Run lint, type-check, and test suite.                                                                                                                                              |
| `npm run deploy` | Build and deploy to <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Workers</Terminology>.             |
| `npm run clean`  | Remove the build output directory.                                                                                                                                                 |
| `npm run tail`   | Tail live logs from the deployed <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Worker</Terminology>. |
