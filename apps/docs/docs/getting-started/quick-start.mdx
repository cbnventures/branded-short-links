Install Branded Short Links and deploy your first short link to <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Workers</Terminology>.

Before you begin, you'll need a Cloudflare account with a registered domain — Cloudflare offers [domain registration](https://www.cloudflare.com/products/registrar/) at cost with no markup. You'll generate a Cloudflare <Terminology title="Cloudflare credential authorizing CLI deployments" to="/docs/reference/terminology#api-token">API token</Terminology> during the [Deploy](#5-deploy) step below.

## Install

Install the package globally to use the `bsl` command anywhere:

```bash
npm install -g branded-short-links
```

Or run it directly without installing:

```bash
npx branded-short-links
```

Both `branded-short-links` and `bsl` are registered as CLI aliases — they do the same thing.

The first command that needs configuration copies the starter template included with the npm package to your platform config directory. Global and `npx` installs don't require a repository clone or a separately downloaded `config.sample.json`.

## First-Time Setup

### 1. Launch the Interactive Menu

Run the CLI with no arguments to start the guided setup:

```bash
bsl
```

The interactive menu walks you through configuring settings, links, and <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> step by step.

### 2. Configure Settings

Select **Settings** from the main menu. You're prompted for three values:

- **Worker name** — The name of your <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">Cloudflare Worker</Terminology> (e.g., `branded-short-links`).
- **<Terminology title="domain your shortcodes live on" to="/docs/reference/terminology#base-domain">Base domain</Terminology>** — The custom domain your short links live on (e.g., `example.com`).
- **Show response output** — Whether the <Terminology title="branded page served at the root" to="/docs/reference/terminology#landing-page">landing page</Terminology> displays masked <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology> for debugging. Keep this `false` in production.

### 3. Add Your First Link

Select **Manage Links > Add** from the menu. Each <Terminology title="single shortcode-to-URL config entry" to="/docs/reference/terminology#link-item">link</Terminology> maps a <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology> to a destination URL:

- **<Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">Shortcode</Terminology>** — The path segment after your domain (e.g., `/github`). Must start with `/`.
- **HTTP response** — The redirect status code: `301`, `302`, `303`, `307`, or `308`.
- **Redirect URL** — The full destination URL (e.g., `https://github.com/yourname`).

You can also set an optional **<Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback URL</Terminology>** that catches any request that doesn't match a configured <Terminology title="path segment that maps to a URL" to="/docs/reference/terminology#shortcode">shortcode</Terminology>.

### 4. Add Trackers (Optional)

Attach analytics <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology> that fire server-side on every redirect. Supported types:

- **<Terminology title="Google Analytics 4 tracker type" to="/docs/reference/terminology#ga4">GA4</Terminology>** — <Terminology title="Google Analytics 4 tracker type" to="/docs/reference/terminology#ga4">Google Analytics 4</Terminology> Measurement Protocol
- **<Terminology title="Meta Pixel PageView tracker type" to="/docs/reference/terminology#facebook">Facebook</Terminology>** — Meta Pixel PageView (noscript endpoint)
- **<Terminology title="PostHog event capture tracker type" to="/docs/reference/terminology#posthog">PostHog</Terminology>** — <Terminology title="PostHog event capture tracker type" to="/docs/reference/terminology#posthog">PostHog</Terminology> event capture
- **<Terminology title="push notification tracker type" to="/docs/reference/terminology#ntfy">ntfy</Terminology>** — Push notifications via <Terminology title="push notification tracker type" to="/docs/reference/terminology#ntfy">ntfy</Terminology>
- **<Terminology title="single-URL ntfy notification tracker type" to="/docs/reference/terminology#reverse-proxy-for-ntfy">Reverse Proxy for ntfy</Terminology>** — Push notifications through an [ntfy-reverse-proxy](https://github.com/cbnventures/ntfy-reverse-proxy) endpoint
- **<Terminology title="plain-text webhook tracker type" to="/docs/reference/terminology#plain-text">Plain Text</Terminology>** — <Terminology title="plain-text webhook tracker type" to="/docs/reference/terminology#plain-text">Plain text</Terminology> webhook to any endpoint

See [Trackers](/docs/configuration/trackers/) for setup details on each type.

### 5. Deploy

Run the deploy command from the interactive menu or directly:

```bash
bsl deploy
```

The deploy process validates your <Terminology title="the config.json deployment settings file" to="/docs/reference/terminology#config">config</Terminology>, verifies Cloudflare API permissions, generates `wrangler.toml`, and deploys the <Terminology title="edge function that serves your redirects" to="/docs/reference/terminology#cloudflare-worker">worker</Terminology>. See [Deployment](/docs/deployment/cloudflare/) for the full walkthrough.

## What Happens Next

Once deployed, your short links are live:

| Request                          | Result                                                                                                                                                                                                                                                                                 |
|----------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `https://yourdomain.com/github`  | Fires <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>, redirects to destination                                                                                                                        |
| `https://yourdomain.com/resume`  | Fires <Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">trackers</Terminology>, redirects to destination                                                                                                                        |
| `https://yourdomain.com/unknown` | Redirects to <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback URL</Terminology> (if configured)                                                                                                                     |
| `https://yourdomain.com/`        | Redirects to <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology>, or shows <Terminology title="branded page served at the root" to="/docs/reference/terminology#landing-page">landing page</Terminology> |
| `https://yourdomain.com/missing` | Redirects to <Terminology title="redirect used when no shortcode matches" to="/docs/reference/terminology#fallback-url">fallback</Terminology>, or shows <Terminology title="page shown when nothing else matches" to="/docs/reference/terminology#404-page">404 page</Terminology>    |

<Terminology title="background analytics integration on a link" to="/docs/reference/terminology#tracker">Trackers</Terminology> are optional — you can deploy with an empty `"trackers": []` array and add them later.
